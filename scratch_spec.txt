Assignment Theme
This assignment requires each group to design, implement, and evaluate a Shakespeare-
aware language system using a pretrained Small Language Model (SLM), retrieval-
augmented generation, and structured evaluation. The emphasis is on practical domain
adaptation under realistic computational and organisational constraints.
Introduction and Motivation
Recent advances in natural language processing have been strongly influenced by large-scale
foundation models. However, many real-world organisations do not require, cannot afford, or
cannot govern very large externally hosted models for every downstream task. There is therefore
growing interest in Small Language Models (SLMs) that are computationally efficient, easier
to adapt, and suitable for controlled deployment within corporate, government, educational, or
research environments.
SLMs are particularly attractive where an organisation requires a purpose-built system for a
bounded task, such as internal document question answering, technical support, policy search,
customer assistance, training support, or knowledge-grounded dialogue. In such contexts, the
objective is not to build the largest possible model, but to design a reliable, auditable, and
task-focused language system that can operate under constraints involving cost, privacy, latency,
maintainability, and domain specificity.
This assignment explores that paradigm through a controlled domain adaptation task. Each
group will adapt a pretrained language model to support interaction with selected Shakespearean
plays. The task is deliberately chosen because Shakespearean text differs significantly from
contemporary English in vocabulary, syntax, idiom, and cultural context. At the same time, the
assignment does notassume that all students have previously studied Shakespeare. The system
should therefore be designed to help a beginner understand and interact with the plays.
Pedagogical Focus
This assignment evaluates your ability to design, adapt, and evaluate a language model-
based system under constraints. It is not an exercise in training a large model from
scratch or competing on GPU resources. Nor is it an exercise to maximise model size or
computational scale.
Problem Statement
Each group must design and implement a Shakespeare-aware language system that enables
a user with little or no prior exposure to Shakespeare to ask questions, retrieve relevant evidence,
and receive useful explanations or short stylised responses.
The system must demonstrate the following capabilities:

Technical Requirements and Constraints
Model Constraints
Students must use a pretrained SLM or an approved hosted language model. The purpose of
the assignment is to adapt and evaluate an existing model, not to pretrain a model from scratch.
Important Constraint
Training a language model from scratch is not permitted . Full-scale pretraining, dis-
tributed training, custom CUDA engineering, or large-scale hyperparameter search are
outside the scope of this assignment.
Acceptable adaptation strategies include:
•prompt engineering;
•retrieval-augmented generation (RAG);
•lightweight fine-tuning, such as LoRA or QLoRA, where feasible;
•hybrid approaches combining retrieval and controlled generation.
If using a hosted model, groups must justify how their system design aligns with the principles
of small, deployable, or resource-constrained models.
Mandatory Architecture
ARetrieval-Augmented Generation (RAG) pipeline is mandatory. At minimum, the
system must include:
1. document preparation and chunking;
2. embedding-based indexing;
3. retrieval of relevant passages for a user query;
4. generation conditioned on the retrieved context;
5. display of retrieved evidence alongside, or immediately below, the generated answer.
Retrieved passages must be demonstrably used in generating responses. Systems that do not
meaningfully integrate retrieved context into generation will be penalised.

System Requirements
The implemented system must support the following four interaction types.
Concept Explanation
The system should answer questions such as:
•Who is Hamlet?
•What is the role of Lady Macbeth?
•What is the conflict between the Montagues and the Capulets?

Contextual Question Answering
The system should answer questions requiring understanding of events and motivations, such as:
•Why does Macbeth kill Duncan?
•Why does Hamlet delay taking revenge?
•Why is Juliet conflicted after meeting Romeo?
Evidence Retrieval
For each substantive answer, the system should retrieve relevant source passages. The retrieved
evidence should include available metadata such as play, act, scene, speaker, and excerpt.
Stylised Response Generation
The system should be able to generate a short response in a Shakespearean style. Stylised
responses must be limited to 150 words . The system should not present creative stylised output
as factual evidence. Stylised responses must remain interpretable and should not sacrifice clarity
for stylistic imitation.
Evaluation Requirements
Each group must conduct a structured evaluation using 10–15 evaluation questions .
The evaluation set must contain:
•5 instructor-provided questions ; and
•5–10 group-designed questions created by the student group.
The instructor-provided questions will establish a common basis for comparison across groups.
The group-designed questions will allow each group to test additional aspects of its system,
including robustness, style control, retrieval quality, and usefulness for beginners.
Each group must implement:
•a baseline system (e.g., prompt-only or minimal retrieval);
•an improved system (RAG-based).
The report must include a comparison between the baseline and the improved system.
Evaluation Criteria
Each group must evaluate the system using the following criteria:
1. Correctness: Is the answer factually accurate with respect to the selected plays?
2. Grounding: Is the answer supported by retrieved evidence?
3. Retrieval relevance: Are the retrieved passages appropriate for the question?
4.Usefulness: Would the answer help a beginner understand the relevant character, event,
or theme?
5.Style quality: For stylised generation, does the response reasonably reflect Shakespearean
tone without becoming incomprehensible?

Scoring
Groups should define a simple and consistent scoring scale (e.g., 1–5 or low/medium/high)
for each evaluation criterion and apply it consistently across all evaluation questions.
The report must include both successful examples and failure cases. Failure analysis is an
important part of the assignment and should discuss hallucination, irrelevant retrieval, incomplete
answers, misleading style generation, or poor handling of ambiguous questions.
Marks are awarded based on the quality of reasoning, justification, and analysis, not merely
on whether outputs appear plausible.

Appendix
Practical Implementation Guide
This appendix provides practical guidance on how to approach the assignment. It is intended to
reduce unnecessary uncertainty about tools, workflow, and implementation choices. It does not
prescribe a single correct solution. Groups are still expected to make, justify, and evaluate their
own design decisions.
Recommended Development Workflow
A sensible workflow for this assignment is as follows:
1. Inspect the three Shakespeare plays provided for the assignment.
2.Inspect the provided structured dataset and decide how it will be represented for retrieval.
3. Prepare the selected records, fields, and metadata for indexing.
4.Split the text into meaningful retrieval units, such as scenes, speaker turns, or short
passages.
5. Generate embeddings for each retrieval unit.
6. Build a retrieval index using a vector search method.
7. Connect the retriever to a SLM using a Retrieval-Augmented Generation pipeline.
8. Test the system using the instructor-provided and group-designed questions.
9. Analyse failures and refine the system.
10. Prepare the final report, demonstration, source code, and GenAI usage log.
Important clarification on preprocessing A structured version of the Shakespeare dataset
is provided to ensure consistency across groups and to reduce low-level data cleaning effort.
However, groups are still expected to make and justify design decisions regarding how the
data is used within the system. This may include:
•redefining or refining chunk boundaries;
•selecting or modifying which fields are used for retrieval;
•augmenting the data with summaries or additional metadata;
•filtering or restructuring records for improved retrieval quality.
Therefore, “preprocessing” in this assignment refers to thoughtful preparation and represen-
tation of the dataset for retrieval and generation, not raw text cleaning.

Chunking Strategy
The retrieval system depends strongly on how the text is divided into chunks. Groups should
avoid arbitrary splitting that destroys context. Suitable chunking strategies include:
•one chunk per scene;
•one chunk per speaker turn;
•fixed-size overlapping text chunks;
•semantically meaningful passages grouped by event or topic.
Each chunk should retain metadata so that retrieved evidence can be traced back to the play,
act, scene, and speaker.

completed using a pretrained SLM or an approved hosted model.
Acceptable options include:
•a hosted SLM accessed through an API;

Prompt Design
The generation component should be prompted to use retrieved context rather than relying only
on its general prior knowledge. A useful prompt should instruct the model to:
•answer using the retrieved passages;
•indicate uncertainty when the evidence is insufficient;
•avoid inventing unsupported details;
•provide beginner-friendly explanations;
•produce stylised Shakespearean output only when requested.
Groups should include representative prompts in the report or appendix and explain how the
prompts evolved during development.
